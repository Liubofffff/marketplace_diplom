## О проекте

Проект реализует небольшой аналитический контур для работы с данными маркетплейса:

1. получение данных с помощью Python-скриптов;
2. загрузка данных в PostgreSQL;
3. хранение данных в реляционной базе данных;
4. подготовка SQL-запросов для анализа;
5. визуализация результатов в Metabase;
6. автоматизация ежедневной загрузки данных.

Проект может использоваться как пример организации небольшого ETL-процесса и аналитической инфраструктуры на локальном сервере.

## Архитектура проекта

Общая схема работы:

```text
Источник данных
      │
      ▼
Python-скрипты
      │
      ▼
PostgreSQL
      │
      ├──────────────► SQL-запросы
      │
      ▼
   Metabase
      │
      ▼
Аналитические отчёты
```

Для развёртывания PostgreSQL, pgAdmin и Metabase используется Docker Compose.

## Установка и запуск

### 1. Клонирование репозитория

```bash
git clone <REPOSITORY_URL>
cd marketplace_diplom
```

Замените `<REPOSITORY_URL>` на URL репозитория.

### 2. Создание файла `.env`

Создайте файл `.env` в корневой директории проекта:

```bash
cp .env.example .env
```

Откройте файл и укажите собственные значения переменных.

### 3. Запуск инфраструктуры

Запустите контейнеры:

```bash
docker compose up -d
```

Проверить состояние контейнеров:

```bash
docker compose ps
```

После успешного запуска будут доступны следующие сервисы:

| Сервис     |   Порт | Назначение               |
| ---------- | -----: | ------------------------ |
| PostgreSQL | `5432` | база данных              |
| pgAdmin    | `8080` | управление PostgreSQL    |
| Metabase   | `3000` | аналитика и визуализация |

## Настройка переменных окружения

Пример файла `.env`:

```dotenv
POSTGRES_DB=marketplace_db
POSTGRES_USER=your_username
POSTGRES_PASSWORD=your_password
POSTGRES_PORT=5432

METABASE_PORT=3000

PGADMIN_EMAIL=your_email@example.com
PGADMIN_PASSWORD=your_password
PGADMIN_PORT=8080
```

### Важно

Файл `.env` содержит конфиденциальные данные и **не должен попадать в Git**.

В репозитории рекомендуется хранить только `.env.example`:

```dotenv
POSTGRES_DB=marketplace_db
POSTGRES_USER=
POSTGRES_PASSWORD=
POSTGRES_PORT=5432

METABASE_PORT=3000

PGADMIN_EMAIL=
PGADMIN_PASSWORD=
PGADMIN_PORT=8080
```

Добавьте `.env` в `.gitignore`:

```gitignore
.env.example
.venv/
__pycache__/
*.log
```

## Создание виртуального окружения

Создайте виртуальное окружение:

```bash
python3 -m venv .venv
```

Активируйте его:

```bash
source .venv/bin/activate
```

Установите зависимости:

```bash
pip install -r requirements.txt
```

Для обновления `pip` перед установкой зависимостей можно выполнить:

```bash
python -m pip install --upgrade pip
```

## Инициализация базы данных

После запуска PostgreSQL необходимо создать таблицу.

Выполните:

```bash
docker exec -i postgres psql -U "your_username" -d marketplace_db < sales.sql
```

Если переменные окружения не экспортированы в текущую оболочку, можно выполнить команду непосредственно с учётными данными:

```bash
docker exec -i postgres psql -U "your_username" -d marketplace_db < sql/create_table.sql
```

> Если имя контейнера PostgreSQL отличается от `postgres`, его необходимо заменить в команде.

Проверить созданную таблицу можно через pgAdmin или командную строку PostgreSQL.

## Загрузка исторических данных

Для первоначальной загрузки данных за определённый период используется:

```text
run_date_range.py
```

Перед запуском необходимо указать требуемый диапазон дат в файле `run_date_range.py`.

После настройки выполните:

```bash
python run_date_range.py
```

Для проверки результата можно подключиться к PostgreSQL и выполнить SQL-запрос:

```sql
SELECT *
FROM <table_name>
LIMIT 10;
```

## Автоматическая загрузка данных

Для ежедневной загрузки данных за предыдущий день используется:
_(по умолчанию при запуске без параметров скрипт загружает данные за вчерашний день)_
```text
load_day.py
```
Скрипт можно запускать автоматически с помощью `cron`.

Откройте таблицу заданий:

```bash
crontab -e
```

Добавьте:

```cron
0 7 * * * cd /path/to/marketplace_diplom && /path/to/marketplace_diplom/.venv/bin/python load_day.py >> /path/to/marketplace_diplom/load_day.log 2>&1
```

Например:

```cron
0 7 * * * cd /home/liu/marketplace_diplom && /home/liu/marketplace_diplom/.venv/bin/python load_day.py >> /home/liu/marketplace_diplom/load_day.log 2>&1
```

Расшифровка:

```text
0 7 * * *
│ │ │ │ │
│ │ │ │ └── день недели
│ │ │ └──── месяц
│ │ └────── день месяца
│ └──────── час
└────────── минута
```

Таким образом, `load_day.py` будет запускаться **каждый день в 07:00**.

### Проверка cron

Посмотреть установленные задания:

```bash
crontab -l
```

Проверить журнал выполнения:

```bash
tail -f /home/liu/marketplace_diplom/load_day.log
```

> Для cron рекомендуется использовать абсолютные пути. Это позволяет избежать проблем с текущей рабочей директорией и переменными окружения.

## Metabase

После запуска контейнера Metabase доступен на порту `3000`.

```text
http://<SERVER_IP>:3000
```

При первом запуске необходимо выполнить первоначальную настройку Metabase и подключить PostgreSQL в качестве источника данных.

Параметры подключения к PostgreSQL внутри Docker-сети:

```text
Host: postgres
Port: 5432
Database: marketplace_db
User: your_username
Password: your_password
```

> Если Metabase и PostgreSQL находятся в одном Docker Compose, для подключения из контейнера Metabase следует использовать имя сервиса PostgreSQL (`postgres`), а не `localhost`.

Готовые SQL-запросы и экспортированные отчёты находятся в:

```text
metabase/
├── pdf/
└── queries/
```

## Безопасность

Не публикуйте в репозитории:

* пароли;
* API-ключи;
* токены;
* содержимое `.env`;
* другие секретные параметры доступа.

Перед публикацией проекта проверьте:

```bash
git status
```

и убедитесь, что `.env` и другие конфиденциальные файлы не добавлены в Git.

Для публичного репозитория рекомендуется использовать `.env.example` с пустыми или демонстрационными значениями.
